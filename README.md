# BudgetBuddy (iOS SwiftUI)

Native iOS budgeting app with:
- Monthly budget categories, with add/delete (deleting a category cascades
  and removes its transactions)
- Transaction tracking, scoped to a selected month with back/forward
  navigation (forward is capped at the current month)
- Dashboard totals (budget, spent, remaining), using `Decimal` throughout
  for money so totals aren't subject to floating-point rounding error
- Local persistence via `UserDefaults`, with per-dataset corrupt-data
  recovery: if a saved payload fails to decode, the raw bytes are preserved
  under a backup key instead of being silently discarded, and a recovery
  sheet lets you restore (including a partial recovery when only some
  entries are readable) or discard the affected dataset

## Requirements

- Xcode 15+
- XcodeGen (`brew install xcodegen`)

## Run

```bash
git clone https://github.com/TuckerWarlock/BudgetBuddy.git
cd BudgetBuddy
xcodegen generate
open BudgetBuddy.xcodeproj
```

## Testing

The project has two test targets, both generated by XcodeGen alongside the
app target.

- **BudgetBuddyTests** (unit tests): covers `BudgetStore` -- persistence,
  month navigation, category/transaction CRUD, and the corrupt-data
  recovery flow. Run with `Cmd+U` in Xcode, or from the command line:

  ```bash
  xcodebuild test \
    -project BudgetBuddy.xcodeproj \
    -scheme BudgetBuddy \
    -destination 'platform=iOS Simulator,name=iPhone 17' \
    -only-testing:BudgetBuddyTests
  ```

- **BudgetBuddyUITests**: drives the app through Accessibility, e.g. the
  month-navigation chevrons. Useful for catching regressions in whether a
  control is reachable and does the right thing when tapped through
  Accessibility -- but XCUITest taps *through the accessibility tree*, so it
  cannot catch a real, physical-tap failure where a control is fully valid
  in that tree but a SwiftUI `List` row's own gesture recognizer silently
  swallows the actual touch before the control sees it. This project has hit
  that exact bug twice (the month chevrons, then the data-recovery sheet's
  Restore/Discard buttons); both are fixed with `.buttonStyle(.plain)`, but
  a UI test suite going green is not evidence that kind of control works --
  any new tappable control added inside a `List`/`Form` row needs a manual
  tap in the simulator, not just a passing automated test.

  ```bash
  xcodebuild test \
    -project BudgetBuddy.xcodeproj \
    -scheme BudgetBuddy \
    -destination 'platform=iOS Simulator,name=iPhone 17' \
    -only-testing:BudgetBuddyUITests
  ```
